## 시작

### ① UTM에서 VM 시작

```
UTM 앱 실행 → VM 선택 → ▶ 재생
```

부팅 30초~1분.

### ② 맥이 잠들지 않게 (서버를 계속 켜둘 때만)

맥 터미널에서:

```bash
caffeinate -imsu
```

- 이 창을 켜둔 채로 둔다. `Ctrl-c` 로 종료
- `-d` 를 빼면 화면만 꺼지고 시스템은 안 잔다
- ⚠️ **뚜껑을 닫으면 `caffeinate` 로도 못 막는다.** 전원 연결 + 뚜껑 열어둘 것

### ③ 한 줄 상태 점검

```bash
ssh rhel2 'date; systemctl is-active nginx firewalld chronyd' && \
curl -sk -o /dev/null -w "웹: %{http_code}\n" https://<DB_SERVER_IP>
```

기대 결과: 현재 시각 / `active` 3개 / `웹: 200`

### ④ 시계 확인 — 일시정지 후 재개했다면 필수

`date` 결과가 맥과 다르면:

```bash
ssh rhel2 'sudo chronyc makestep'
```

> VM을 일시정지했다 재개하면 그 사이 시간만큼 시계가 뒤처진다. TLS 인증서·로그·cron이 전부 어긋나므로 반드시 맞출 것.

---

## 종료

```bash
ssh rhel2 'sudo poweroff'
```

⚠️ **UTM 창을 그냥 닫는 일시정지가 아니라 정상 종료할 것.** 그래야 시계가 안 어긋나고 파일시스템이 안전하다.

`caffeinate` 창은 `Ctrl-c`.

## 자주 쓰는 확인 명령

```bash
# 서비스 상태
systemctl is-active nginx firewalld chronyd
systemctl status nginx --no-pager

# 리스닝 포트
ss -tln | grep -E ":80|:443|:22"

# 방화벽
sudo firewall-cmd --list-all

# SELinux
getenforce
ls -Z /usr/share/nginx/html/

# 디스크
df -hT -x tmpfs -x devtmpfs

# 시각
date; chronyc tracking

# 웹 응답 (캐시 없이)
curl -sk -o /dev/null -w "%{http_code}\n" https://<DB_SERVER_IP>
```

## 코드 업데이트 배포

GitHub에 새 커밋을 올린 뒤:

```bash
ssh rhel2
cd ~/miniproject_web
git pull
npm install          # 의존성이 바뀌었을 때만
npm run build
sudo cp -r dist/* /usr/share/nginx/html/
ls -lZ /usr/share/nginx/html/    # 라벨이 httpd_sys_content_t 인지 확인
```

브라우저에서 확인할 때 **강제 새로고침**(`Cmd+Shift+R`). 안 되면 시크릿 창.

> 나중에 이 과정을 스크립트로 만들면 4단계(bash 스크립트) 실습이 된다.

## 문제 해결

| 증상 | 확인 순서 |
|---|---|
| `ssh` 가 timeout | VM이 켜져 있는지 → `ping IP` → UTM 창 확인 |
| 웹이 안 뜸 | `systemctl is-active nginx` → `ss -tln` → `firewall-cmd --list-all` |
| 403 Forbidden | `ls -Z` 로 SELinux 라벨 확인 → `restorecon -Rv` |
| 파일 바꿨는데 반영 안 됨 | `curl` 로 확인 → 다르면 **브라우저 캐시** |
| 카메라가 안 켜짐 | `https://` 로 접속했는지 확인 (`http://` 는 차단됨) |
| 서비스 시작 실패 | `systemctl status` → `journalctl -xeu 서비스명` → `nginx -t` → `ss -tlnp`(포트 충돌) → `ausearch -m AVC`(SELinux) |
| 시각이 이상함 | `sudo chronyc makestep` |

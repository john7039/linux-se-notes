## 🔧 해온 것

**서버 구축**
- RHEL 10 설치부터 SSH 키 인증까지 자력 구축 (2대)
- 고정 IP(`nmcli`), 방화벽(`firewalld`), SELinux Enforcing 유지
- SSH 포트 변경 — `sshd_config` + SELinux 포트 라벨 + 방화벽 세 곳을 함께
- 비밀번호 인증 비활성화 (키 전용)

**스토리지**
- LVM 전체 사이클: `lvcreate` → `mkfs` → `mount` → `/etc/fstab` → 재부팅 검증
- 무중단 확장 (`lvextend -r`)
- 그룹 + setgid 로 공유 디렉토리 구성

**배포·운영**
- Vite 빌드 결과물을 nginx로 서빙, 자체 서명 인증서로 HTTPS 구성
- `systemctl enable` · `firewall-cmd --permanent` 로 재부팅 후 자동 복구 검증
- 상태 점검 스크립트 작성

**장애 대응**
- 무엇이 고장났는지 모르는 상태에서 진단·복구하는 훈련 진행
- [훈련 기록](2026-08-03/장애복구훈련.md) — 진단 과정과 근거를 명령어 단위로 정리

## 💡 정리하며 얻은 원칙

### 임시 vs 영구 — 리눅스 전반을 관통하는 구조

| 영역 | 임시 | 영구 |
|---|---|---|
| 서비스 | `systemctl start` | `systemctl enable` |
| 방화벽 | `firewall-cmd --add-xxx` | `--permanent` + `--reload` |
| 마운트 | `mount` | `/etc/fstab` |
| SELinux boolean | `setsebool` | `setsebool -P` |

### 진단 — 실패 방식으로 범위를 가른다

```
timeout  →  패킷이 중간에서 막힘       →  방화벽 · 네트워크
refused  →  패킷은 도달, 받는 게 없음   →  서비스 · 리스닝 설정
403      →  파일은 있는데 못 읽음       →  권한 · SELinux 라벨
404      →  파일을 못 찾음             →  경로 설정
```

### 설정값 ≠ 실제 동작

`sshd -T`, `nginx -t` 는 **파일에 뭐라고 적혀 있는지**만 보여준다.
반영 여부는 `ss -tln`, 실제 접속 시도로 확인한다.

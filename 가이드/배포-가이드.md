# 배포 가이드 — GitHub 프로젝트를 리눅스 서버에 올려 운영하기

> **목표**: 어떤 GitHub 프로젝트든 리눅스 서버에 배포해서 24시간 서비스로 운영한다.
> 이 문서만 보고 처음부터 끝까지 할 수 있게 만든 절차서.

**최종 갱신**: 2026-08-03 (Posture Guard 배포 기준)

---

# STEP 0. 전제 — 서버가 준비되어 있어야 함

아래가 안 되어 있으면 [서버 구축 노트](../2026-07-30/서버구축-실습.md)를 먼저.

- [ ] 서버에 SSH 키 인증으로 접속됨 (`ssh 별칭`)
- [ ] 고정 IP
- [ ] `sudo` 사용 가능한 계정 (root 아님)
- [ ] 방화벽 활성, SELinux Enforcing
- [ ] **시각이 정확함** ← `date` 로 확인. 틀리면 `sudo chronyc makestep`

```bash
ssh 별칭 'whoami; hostname; date; getenforce; systemctl is-active firewalld'
```

> ⚠️ `whoami` 가 `root` 면 **일반 계정으로 다시 접속**할 것. root로 배포하면 안 된다.

# STEP 1. 배포 대상 파악 (코드 받기 전에)

**어떤 프로젝트인지에 따라 배포 방식이 완전히 달라진다.** 먼저 확인한다.

```bash
# 맥에서 미리 클론해 훑어봐도 됨
git clone <저장소>
cd <프로젝트>

cat README.md              # 실행 방법
cat package.json           # Node 프로젝트인가
cat requirements.txt       # Python 프로젝트인가
ls                         # 전체 구조
```

## 판별표

| 확인 | 유형 | 배포 방식 |
|---|---|---|
| `npm run build` 로 `dist/` 생성 | **정적 사이트** | nginx가 파일만 서빙 |
| 서버 코드가 포트를 열고 대기 (`app.listen`, `uvicorn`, `flask run`) | **백엔드 있음** | systemd 서비스 등록 + nginx 리버스 프록시 |
| DB 접속 코드가 있음 | **DB 필요** | MariaDB/PostgreSQL 설치·연동 |
| 카메라·마이크 사용 (`getUserMedia`) | — | **HTTPS 필수** |

```bash
grep -rn "listen(\|uvicorn\|flask run\|app.run" .    # 백엔드 존재 여부
grep -rn "getUserMedia" .                            # HTTPS 필요 여부
grep -rn "localStorage" .                            # 데이터 저장 위치
```

> 📌 **Posture Guard 사례**: 백엔드 없음 + localStorage + `getUserMedia` 사용
> → **정적 사이트 + HTTPS 필수**

# STEP 2. 런타임 설치

프로젝트에 맞는 것만.

```bash
sudo dnf install -y git                 # 공통

```

**확인**

```bash
for c in git node npm nginx; do printf "%-6s " $c; command -v $c >/dev/null && $c --version 2>&1|head -1 || echo "미설치"; done
```

# STEP 3. 코드 받고 빌드

```bash
cd ~                                    # 반드시 홈 디렉토리 (root의 /root 아님)
git clone https://github.com/사용자/저장소.git
cd 저장소
```

## 정적 사이트 (Vite/React/Vue 등)

```bash
npm install
npm run build          # → dist/ 또는 build/ 생성
ls dist/               # index.html, assets/ 확인
```

> ⚠️ **`npm run dev` 를 쓰면 안 된다.** 개발용 서버라 성능·보안이 운영에 맞지 않고 **터미널을 닫으면 죽는다.** 배포는 `build` 결과물을 웹서버가 서빙한다.

## Python 백엔드

```bash
python3 -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

> 가상환경(`venv`)을 쓰는 이유: 시스템 파이썬을 오염시키지 않고, 프로젝트별로 버전을 분리한다.

# STEP 4. 배포

## 4-A. 정적 사이트

```bash
sudo cp -r dist/* /usr/share/nginx/html/
```

**⚠️ 문서 루트에 심볼릭 링크가 있으면 먼저 지운다** (nginx 기본 `index.html` 이 링크인 경우가 있음)

```bash
ls -l /usr/share/nginx/html/index.html      # 맨 앞이 l 이고 -> 가 보이면 링크
sudo rm -f /usr/share/nginx/html/index.html # 링크 제거 후 다시 복사
sudo cp -r dist/* /usr/share/nginx/html/
```

**SELinux 라벨 확인 — 필수**

```bash
ls -lZ /usr/share/nginx/html/
```

`httpd_sys_content_t` 가 아니면:

```bash
sudo restorecon -Rv /usr/share/nginx/html/
```

> `cp` 는 목적지 기본 라벨을 받지만, `mv` 는 원본 라벨을 끌고 와서 **403 Forbidden** 이 난다. **항상 `cp`.**

## 4-B. 백엔드가 있는 경우 — systemd 서비스 등록

`/etc/systemd/system/myapp.service` 생성:

```ini
[Unit]
Description=My Application
After=network.target
# DB를 쓰면: After=network.target mariadb.service

[Service]
Type=simple
User=<DB_USER>
WorkingDirectory=/home/<DB_USER>/저장소
ExecStart=/home/<DB_USER>/저장소/venv/bin/python app.py
Restart=always
RestartSec=10

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now myapp
systemctl status myapp --no-pager
```

| 항목 | 의미 |
|---|---|
| `Restart=always` | **죽으면 자동 재시작** |
| `RestartSec=10` | 10초 후 재시도 |
| `After=` | 의존 서비스가 뜬 뒤에 시작 |
| `WantedBy=multi-user.target` | 부팅 시 자동 시작 |
| `User=` | **root로 돌리지 않는다** |

nginx 리버스 프록시 (`/etc/nginx/conf.d/myapp.conf`):

```nginx
server {
    listen 80;
    server_name _;
    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
    }
}
```

> SELinux가 nginx의 외부 연결을 막는다. 리버스 프록시를 쓰면 반드시:
> ```bash
> sudo setsebool -P httpd_can_network_connect on
> ```

# STEP 5. nginx 기동 + 방화벽

```bash
sudo systemctl enable --now nginx
sudo firewall-cmd --permanent --add-service=http
sudo firewall-cmd --permanent --add-service=https
sudo firewall-cmd --reload
```

**확인**

```bash
sudo nginx -t                                   # 문법 검사 — 반드시
systemctl is-active nginx
ss -tln | grep -E ":80|:443"
curl -s -o /dev/null -w "%{http_code}\n" localhost
```

맥에서:

```bash
curl -s -o /dev/null -w "%{http_code}\n" http://서버IP
```

# STEP 6. HTTPS

**웹캠·마이크·위치정보를 쓰는 앱은 HTTPS가 아니면 아예 동작하지 않는다.**

| 주소 | 카메라 |
|---|---|
| `https://...` | ✅ |
| `http://localhost` | ✅ (예외) |
| `http://192.168.x.x` | ❌ |

## 6-A. 자체 서명 (내부망·실습용)

```bash
sudo openssl req -x509 -nodes -newkey rsa:2048 \
  -keyout /etc/pki/tls/private/myapp.key \
  -out /etc/pki/tls/certs/myapp.crt \
  -days 365 \
  -subj "/C=KR/ST=Seoul/O=MyApp/CN=<DB_SERVER_IP>" \
  -addext "subjectAltName=IP:<DB_SERVER_IP>"

sudo chmod 600 /etc/pki/tls/private/myapp.key
```

> **`-addext subjectAltName` 은 최신 브라우저 필수.** 없으면 CN만으로는 거부된다.
> **`-nodes`** 는 개인키에 암호를 안 거는 옵션. 걸면 nginx 시작마다 암호를 물어본다.

`/etc/nginx/conf.d/ssl.conf`:

```nginx
server {
    listen 443 ssl;
    server_name <DB_SERVER_IP>;

    ssl_certificate     /etc/pki/tls/certs/myapp.crt;
    ssl_certificate_key /etc/pki/tls/private/myapp.key;

    root  /usr/share/nginx/html;
    index index.html;
}
```

```bash
sudo nginx -t && sudo systemctl reload nginx
```

**한계**: 브라우저가 `NET::ERR_CERT_AUTHORITY_INVALID` 경고를 띄운다. 본인만 쓸 때는 "고급 → 이동"으로 넘어가면 되지만, **남에게 공개하는 서비스에는 쓸 수 없다.**

## 6-B. 정식 인증서 (공개 서비스) — 도메인 필요

```bash
sudo dnf install -y certbot python3-certbot-nginx
sudo certbot --nginx -d 내도메인.com
```

certbot이 nginx 설정을 자동으로 고치고, 갱신도 자동 등록한다.

**전제**: 도메인이 있고, 그 도메인이 이 서버를 가리키고, 80번 포트로 외부에서 접근 가능해야 함.

# STEP 7. 검증 — 여기까지 해야 "배포 완료"

## 즉시 확인

```bash
# 서버에서
systemctl is-active nginx
sudo nginx -t
ls -lZ /usr/share/nginx/html/        # 라벨 httpd_sys_content_t

# 맥에서
curl -s  -o /dev/null -w "HTTP  %{http_code}\n" http://서버IP
curl -sk -o /dev/null -w "HTTPS %{http_code}\n" https://서버IP
```

## 브라우저 확인

- [ ] `https://서버IP` 접속 → 앱 화면
- [ ] 기능 동작 (카메라 등)
- [ ] **반영이 안 되면 캐시 의심** → `Cmd+Shift+R` 또는 시크릿 창

> `curl` 은 캐시를 안 쓴다. **`curl` 결과와 브라우저가 다르면 캐시 문제.**

## ⭐ 재부팅 검증 — 이게 진짜 완료 조건

```bash
sudo reboot
```

1~2분 뒤, **아무것도 안 했는데** 다시 떠 있어야 한다.

```bash
ssh 별칭 'systemctl is-active nginx firewalld chronyd'
curl -sk -o /dev/null -w "%{http_code}\n" https://서버IP
```

## "재부팅해도 살아남게 하는 법" 총정리

| 요소 | 영구화 방법 |
|---|---|
| 서비스 실행 | `systemctl enable` |
| 방화벽 규칙 | `--permanent` + `--reload` |
| SELinux boolean | `setsebool -P` |
| 마운트 | `/etc/fstab` |
| 시각 동기화 | `chronyd` enable |

**임시로 한 설정은 재부팅에 전부 사라진다.**

# STEP 8. 코드 업데이트 배포

GitHub에 새 커밋을 올린 뒤:

```bash
ssh 별칭
cd ~/저장소
git pull
npm install          # 의존성이 바뀌었을 때만
npm run build
sudo cp -r dist/* /usr/share/nginx/html/
ls -lZ /usr/share/nginx/html/
```

백엔드가 있으면:

```bash
sudo systemctl restart myapp
systemctl status myapp --no-pager
```

브라우저에서 **강제 새로고침**으로 확인.

> 이 과정을 `deploy.sh` 스크립트로 만들면 4단계(bash 스크립트) 실습이 된다.

# 문제 해결

| 증상 | 확인 순서 |
|---|---|
| 웹이 안 뜸 | `systemctl is-active nginx` → `ss -tln` → `firewall-cmd --list-all` |
| **403 Forbidden** | `ls -Z` 로 SELinux 라벨 → `restorecon -Rv` |
| **502 Bad Gateway** | 백엔드가 죽었거나 포트 불일치 → `systemctl status myapp` → `ss -tlnp` |
| 백엔드 연결 실패 | `setsebool -P httpd_can_network_connect on` |
| 파일 바꿨는데 반영 안 됨 | `curl` 로 확인 → 다르면 **브라우저 캐시** |
| 카메라가 안 켜짐 | `https://` 로 접속했는지 |
| 엉뚱한 파일이 바뀜 | 대상이 **심볼릭 링크**였는지 (`ls -l` 맨 앞 글자) |
| 서비스 시작 실패 | `systemctl status` → `journalctl -xeu 서비스명` → `nginx -t` → `ss -tlnp`(포트충돌) → `ausearch -m AVC`(SELinux) |
| 시각이 이상함 | `sudo chronyc makestep` |

## 진단 5단계 (순서대로)

```
① systemctl status 서비스명 --no-pager    에러 메시지
② journalctl -xeu 서비스명                상세 로그
③ 설정 문법 검사 (nginx -t, sshd -T)
④ ss -tlnp                                포트 충돌
⑤ sudo ausearch -m AVC -ts recent         SELinux 차단
```

# 배포 전 체크리스트 (요약)

**준비**
- [ ] `whoami` → root 아님
- [ ] `date` → 시각 정확
- [ ] 프로젝트 유형 파악 (정적 / 백엔드 / DB)

**배포**
- [ ] 런타임 설치 (`git`, `nodejs`/`python3`, `nginx`)
- [ ] `git clone` → 빌드 (`npm run build`, **`dev` 아님**)
- [ ] 문서 루트에 `cp` (**`mv` 아님**) — 심볼릭 링크 확인
- [ ] `ls -lZ` 로 SELinux 라벨 확인
- [ ] 백엔드면 systemd 서비스 등록 (`Restart=always`)
- [ ] `systemctl enable --now nginx`
- [ ] 방화벽 `--permanent` + `--reload`
- [ ] HTTPS 구성 (카메라·마이크 쓰면 필수)

**검증**
- [ ] `nginx -t` 통과
- [ ] 맥에서 `curl` 200
- [ ] 브라우저에서 기능 동작
- [ ] **재부팅 후 자동 복구 확인** ← 이게 완료 조건

## [2026-07-27] `pkill -f` 실행 후 SSH 세션이 끊김

| | |
|---|---|
| **증상** | 프로세스를 정리하려고 명령을 실행했더니 SSH 연결이 `exit 255` 로 끊김 |
| **영향** | 원격 작업 세션 종료. 서비스 영향 없음 (실습 서버) |
| **탐지** | 명령 실행 직후 즉시 — 프롬프트가 돌아오지 않고 `exit 255` |
| **원인** | `pkill -f` 는 프로세스의 **전체 명령줄**을 검사한다. 실행한 명령이 `ssh rhel 'pkill -f "tick"; echo "tick 프로세스 정리됨"'` 이었는데, 뒤쪽 `echo` 메시지에도 `tick` 이 들어 있어 **pkill 을 실행 중이던 원격 셸 자신이 매칭**되어 함께 종료됨 |
| **조치** | 재접속 |
| **검증** | 재접속 후 세션 정상 동작 확인 |
| **재발방지** | ① `pkill -f` 를 쓰기 전에 **`pgrep -af <패턴>` 으로 대상을 먼저 확인**하는 습관 — 확인 후 PID 지정(`kill <PID>`)이 더 안전하다<br>② 죽일 대상 이름을 **같은 줄의 `echo` 메시지에 쓰지 않는다**<br>③ [트러블슈팅 가이드](../가이드/트러블슈팅-가이드.md)에 경고 추가 완료 |
| **소요** | 약 5분 |

> 참고: [7/27 노트](../2026-07-27/ssh-tmux.md) — "4. 실무 함정 2개 (실제로 겪음)"
> 패턴을 꼭 써야 하면 `pkill -f "[t]ick"` — 정규식으로는 `tick` 에 매칭되지만 명령줄 문자열 자체는 `[t]ick` 이라 자기 자신에는 안 걸린다.

## [2026-07-30] `nmcli connection modify` 가 "unknown connection" 으로 실패

| | |
|---|---|
| **증상** | 새로 설치한 서버에 고정 IP를 설정하려는데 명령이 실패 |
| **영향** | 서버가 네트워크에 올라오지 못함 |
| **탐지** | 명령 실행 즉시 — `unknown connection` 오류 |
| **원인** | `nmcli connection modify` 는 **이미 존재하는 연결 프로필**을 고치는 명령인데, 지정한 이름의 프로필이 없었다. 존재 여부를 확인하지 않고 `modify` 부터 실행한 것이 직접 원인 |
| **조치** | `nmcli connection show` 로 프로필 목록을 확인한 뒤, 없으면 `modify` 가 아니라 `add` 로 생성 |
| **검증** | `nmcli connection show` 에 프로필이 보이고, `ip -4 -brief addr` 로 IP가 붙은 것 확인 |
| **재발방지** | ① 네트워크 설정 전 **`nmcli connection show` 로 프로필 존재 여부 먼저 확인** → 있으면 `modify`, 없으면 `add`<br>② [서버 구축 절차](../2026-07-30/서버구축-실습.md) B-6 에 확인 단계로 반영 완료 |
| **소요** | 미상 (기록 안 함) |

## [2026-07-30] 호스트명을 인터페이스 이름으로 착각해 엉뚱한 장치를 설정

| | |
|---|---|
| **증상** | 콘솔에 보인 이름으로 네트워크를 설정했는데 `Connection activation failed` |
| **영향** | 고정 IP 설정 실패. 서버가 네트워크에 올라오지 못함 |
| **탐지** | 명령 실행 즉시 — 활성화 단계에서 실패 |
| **원인** | 콘솔에 뜬 `enp0s2 login:` 을 **네트워크 인터페이스 이름으로 착각**했다. 실제로는 **호스트명**이었다 — 설치할 때 호스트명 입력란에 `enp0s2` 를 넣었던 것. 진짜 인터페이스는 `enp0s1` 이었고, **존재하지 않는 장치**를 설정하려다 실패했다.<br>**로그인 프롬프트의 맨 앞은 언제나 호스트명이다** (`rhel-lab login:` 처럼) |
| **조치** | `ip link` 로 실제 인터페이스 이름(`enp0s1`) 확인 후 다시 설정. 호스트명은 `hostnamectl` 로 정정 |
| **검증** | `ip -4 -brief addr` 로 IP 확인, 맥에서 `ping` 으로 도달 확인 |
| **재발방지** | ① 네트워크 설정 전 **`ip link` 로 실제 인터페이스 이름 확인** → [서버 구축 절차](../2026-07-30/서버구축-실습.md) B-5 에 반영 완료<br>② 로그인 프롬프트 맨 앞 = 호스트명. 인터페이스 이름이 아니다<br>③ **환경 조치 완료(2026-08-04)** — 서버 프롬프트를 청록으로 바꿔 한눈에 구분되게 함 (`PS1='[DB \u@\h \W]$ '`)<br>⚠️ **그런데도 2026-08-17에 재발**했다 — 맥에 써야 할 `/etc/hosts` 를 서버에서 편집. 프롬프트에 `rhel-db` 가 떠 있었는데도 못 알아챘다. **환경은 갖췄으나 읽는 습관이 아직 없다**는 뜻. 다음 재발 시에는 색 구분을 넘어 더 강한 장치(작업 전 `hostname` 출력 강제 등)를 검토할 것 |
| **소요** | 미상 (기록 안 함) |

## [2026-07-29] httpd 서비스 시작 실패 — 80번 포트를 nginx가 이미 사용 중

| | |
|---|---|
| **증상** | `sudo systemctl enable --now httpd` 가 실패 |
| **영향** | 없음 (대체 웹서버 nginx가 이미 동작 중이었음) |
| **탐지** | 명령 실행 즉시 실패 |
| **원인** | **nginx가 이미 80번 포트를 점유**하고 있어서, 나중에 뜬 httpd가 바인딩에 실패했다. 웹서버 두 개가 같은 포트를 쓸 수 없다.<br>근거: `systemctl status httpd` 에 `(98)Address already in use: could not bind to address 0.0.0.0:80`, `httpd -t` 는 `Syntax OK`(설정 문제 아님), `ss -tlnp \| grep :80` 으로 점유 확인, `systemctl is-active nginx` → `active` |
| **조치** | httpd를 띄우지 않음 — 웹서버는 nginx 하나로 유지 |
| **검증** | `ss -tlnp \| grep :80` 으로 nginx가 계속 정상 서비스 중인 것 확인 |
| **재발방지** | ① **웹서버는 nginx 하나로 통일한다. httpd는 설치·기동하지 않는다** — 2026-08-17 확인 결과 `rhel-db` 에 httpd 미설치 상태 유지 중<br>② "서비스가 안 뜬다" 는 추측하지 말고 아래 순서로 진단 → [트러블슈팅 가이드](../가이드/트러블슈팅-가이드.md) 에 반영<br>&nbsp;&nbsp;`① systemctl status` → `② 설정 문법 검사(-t)` → `③ ss -tlnp 포트 충돌` → `④ ausearch -m AVC` |
| **소요** | 미상 (기록 안 함) |
